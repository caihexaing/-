# 12306 单击日期选择流程设计

## 目标

适配当前官方 12306 日期选择器：用户点击目标日期后，日期会自动确认，不存在“确定/完成/确认”按钮。自动化必须在一次目标日期点击后等待页面树刷新，确认日期字段已更新，再进入查询步骤。

## 行为设计

1. 日期字段或日期选择器中只允许定位一个与任务日期匹配的可点击节点。
2. 找到唯一节点后派发一次点击，并保存点击前页面指纹。
3. 点击后每次读取新的官方页面树；不寻找、不点击、不等待任何日期确认按钮。
4. 当日期选择器不再可见、页面指纹发生变化且日期字段上下文显示任务日期时，返回 `DONE`。
5. `DONE` 后由服务进入 `SUBMIT_SEARCH`，在刷新后的页面树中定位并点击“查询”。
6. 目标日期控件不唯一、点击动作未派发、官方页面不是预期页面或在限定时间内没有确认证据时，停止自动操作并进入人工接管，记录具体原因。

## 状态与安全边界

- 保留 `DateSelectionPhase.WAITING_CONFIRMATION` 作为“等待自动关闭/字段更新”的内部状态，但其含义不再包含二次确认按钮。
- 删除日期确认按钮扫描、按钮唯一性判断及相关点击路径，避免把普通“确定”误当作日期确认。
- 不使用全局返回键、不跳回首页、不重复点击目标日期。
- 日期文本必须来自日期字段或其明确的日期字段容器，不能凭页面其它位置出现相同日期就确认。

## 诊断与测试

- 保留“目标日期已点击，等待日期字段更新”“日期已确认，开始查询”等脱敏事件。
- 增加纯逻辑回归测试：单击日期后选择器自动关闭可确认；选择器仍可见时保持等待；确认按钮存在或不存在都不触发按钮动作；目标日期控件不唯一时不授权点击。
- 真机验收记录日期点击动作、点击返回值、点击前后页面指纹、选择器可见性、日期字段证据和进入查询的时间点，不保存账号或证件信息。

## 非目标

本次不修改站点选择、车次/席别选择、乘车人选择、订单提交或 GitHub 发布流程；这些问题另行处理。
