# 12306 自动化流程统一状态机设计

## 目标

一次性收敛当前仓库已记录的自动化问题：官方 App 冷启动与首页导航超时、站点候选重复选择、日期表单推进、查询结果页与席别页误判、普通弹窗误处理、待支付误判、窗口切换/手动返回、状态恢复和重复提交。

本设计只辅助官方 12306 已公开页面操作，不调用未公开下单接口，不绕过验证码、登录、身份核验、风控、候补协议或支付。账号、证件号、手机号、姓名和支付信息不写入诊断报告。不能承诺一定生成订单或固定耗时。

## 统一流程

执行阶段统一为：

```text
SALE_T0
  -> COLD_START
  -> OPENING_OFFICIAL_APP
  -> OPENING_HOME
  -> FILLING_SEARCH_FORM
  -> WAITING_SEARCH_RESULT
  -> VALIDATING_SEARCH_RESULT
  -> TRAIN
  -> SEAT
  -> PASSENGER
  -> ORDER
  -> SUBMIT_ACTION_SENT
  -> WAITING_SERVER_RESULT
  -> PENDING_PAYMENT / TAKEOVER
```

现有 Android 服务仍负责事件接收和动作派发；页面分类、上下文校验、站点确认和提交证据尽量使用无副作用的纯判定函数，方便单元测试。

## 页面与窗口边界

1. 每次处理事件都重新读取 `rootInActiveWindow`，要求根节点包名为 `com.MobileTicket`；包名不匹配、根节点为空或文本为空时不得使用上一次页面树。
2. 用户手动返回、切换应用、系统覆盖层或未知窗口必须记录窗口变化和具体原因。冷启动宽限期内可以等待官方窗口出现，其他阶段直接进入人工接管。
3. 页面快照带有动作代次和短生命周期指纹。任何点击后都必须看到新的快照或明确目标页面变化，旧节点不能继续参与后续点击。
4. 不使用坐标盲点、首页入口回退或 `GLOBAL_ACTION_BACK` 修正上下文冲突；任务上下文冲突时停止并提示用户。

## 冷启动与首页导航

1. `SALE_T0` 由闹钟和服务显式写入，闹钟只接受匹配任务 ID 且任务仍可执行的状态。
2. 前台服务先验证无障碍服务和官方包是否可启动；官方不在前台时尝试一次启动，并记录尝试次数、启动失败和等待起止时间。
3. 检测到官方首页后，只定位唯一的车票/查询入口；公告、活动和首页导航文本不会被当作查询按钮。
4. 查询表单按出发站、到达站、日期顺序处理。每个字段有 `IDLE`、`WAITING_CANDIDATE`、`WAITING_CONFIRMATION`、`CONFIRMED`，缺证据只等待，候选不唯一或动作失败立即接管。
5. 查询点击最多派发一次，之后等待结果页加载/部分结果/完整结果状态；固定冷却只用于重复保护，不作为页面已切换的证明。

## 结果、席别和乘车人

1. 结果列表证据优先于席别页证据。包含车次、席别和“预订”的文本仍识别为查询结果；席别页必须有独立的选择席别语义且没有结果列表证据。
2. 完整结果页必须联合校验日期、出发站、到达站和目标车次。字段缺失进入有限等待，字段冲突、非结果页或控件不唯一立即接管。
3. 目标车次、席别和乘车人操作都限定在对应卡片/容器内；每次点击后重新读树并验证页面阶段，不能沿用旧树。
4. 乘车人必须唯一匹配；同名、多条候选、找不到或需要身份核验时停止。

## 弹窗与提交结果

1. 仅对可见、结构明确、关闭控件唯一且语义为普通提示的弹窗自动关闭。公告/活动内容不点击，关闭控件不唯一时人工接管。
2. 订单确认页字段不匹配时不得提交。找到唯一可点击的“提交订单”后再获取持久提交锁；动作返回 `false` 时释放锁，返回 `true` 只记录 `SUBMIT_ACTION_SENT`。
3. 提交后只进入等待结果状态。必须在官方窗口内累计核对订单号、日期、车次、席别、乘车人和金额等订单证据，才写入 `PENDING_PAYMENT`；单个“待支付”关键词、首页隐藏文本或本地点击返回值均不足以确认。
4. 处理中、排队、无票、重复订单、验证码、风控、身份核验、网络错误和未知页面分别记录并接管，不自动重试提交。

## 持久化与诊断

任务持久化阶段、最后一次官方根包名、页面状态、动作结果、快照指纹、动作代次、等待计数、失败原因和关键时间点（`T0` 开售、`T1` 结果页、`T2` 目标控件、`T3` 预订、`T4` 乘车人、`T5` 提交、`T6` 官方订单证据）。窗口变化或任务配置变化使旧快照失效。诊断只保存脱敏状态、哈希和计数，不保存账号、证件、手机号、姓名或支付信息。

## 测试与验收

- 页面分类：结果页/席别页重叠文本、部分结果、首页隐藏待支付文案。
- 站点确认：输入文字不能确认、无候选证据不能确认、点击后无快照变化不能确认、候选不唯一不能点击、正确候选点击后才能推进。
- 冷启动：闹钟任务 ID/状态过滤、启动失败恢复、非官方窗口、空树、手动返回和旧快照失效。
- 动作幂等：查询只发一次、提交锁在按钮前不占用、点击拒绝可释放、点击成功后不重复提交。
- 结果证据：提交前待支付关键词不成功，提交后分事件累计完整订单字段才能成功。
- 构建验收：`testDebugUnitTest`、`assembleDebug`；真机上验证首页、站点、日期、结果、席别、乘车人和提交后的官方页面变化。真机验收前版本说明保持实验性，不承诺订单生成。

## 发布边界

版本递增并发布正式 GitHub Release，说明修复范围、测试结果和真机验证限制。后台启动限制、厂商电池策略、无障碍树差异及官方页面改版必须在界面和诊断中明确提示。
