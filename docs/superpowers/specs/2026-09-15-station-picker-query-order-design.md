# 车站选择查询顺序与诊断改进设计

## 背景

v0.4.27 在 12306 车站选择页先扫描全页候选，再确认顶部搜索框回读。页面默认的“常用车站”列表可能已经包含目标站名，导致候选分支反复等待，搜索框的 `ACTION_SET_TEXT` 永远不会发送。最新诊断已确认流程停在 `DEPARTURE`，没有进入日期、结果页或订单流程。

## 目标

- 车站选择页必须先确认唯一的顶部搜索框并写入目标站名。
- 只有同一输入框回读目标站名后，才允许扫描和点击过滤后的候选。
- 默认“常用车站/热门车站”列表不能作为过滤完成证据。
- 输入框节点重建或边界变化时安全重新绑定，并重新写入、重新回读。
- 车站选择阶段显式记录查询写入、回读、候选过滤和选择确认状态。
- 保持点击后刷新页面树、字段显示确认和人工接管边界，不改变日期、车次、席别和订单提交规则。

## 方案

`OfficialSearchInteractor.fillStation()` 按以下顺序执行：

1. 识别车站选择页和唯一顶部输入框。
2. 若输入框尚未回读目标站名，优先聚焦并发送一次 `ACTION_SET_TEXT`。
3. 等待同一输入框回读；节点重建时按稳定布局/语义重新绑定，并清除旧写入确认。
4. 输入确认后，仅从过滤结果或明确刷新后的候选容器中查找唯一目标站。
5. 点击候选一次，等待页面树刷新、选择页关闭和对应表单字段显示目标站。

状态使用 `WAITING_QUERY_WRITE`、`WAITING_QUERY_READBACK`、`WAITING_FILTERED_CANDIDATE`、`WAITING_CONFIRMATION`，并把状态、输入框 key、是否已写入/回读、候选作用域和数量写入脱敏诊断。

## 持久化诊断

在 `TicketTask` 中增加稳定页面状态、未知原因、车站查询阶段、写入/回读标志、候选作用域/数量及时间戳。`UNKNOWN` 仍可记录为最后一次事件，但不覆盖最后稳定页面。旧任务读取时使用默认值保持兼容，导出报告只包含这些状态字段，不保存账号、证件、手机号或支付信息。

## 验证

- 增加纯函数测试覆盖新状态和查询顺序。
- 保留现有车站选择确认测试，并增加“默认列表含目标站时必须先写入查询”的回归场景。
- 运行 `test` 和 `assembleDebug`；真机验收需验证汉口 -> 潜江场景中输入、回读、候选点击和表单回填的完整链路。
