# APK 更新下载性能设计

## 目标

减少 GitHub 网络波动造成的更新等待和重复下载，让用户能看清连接、下载和校验阶段，并在下载中断后继续使用已保存的临时文件。

## 下载流程

1. 检查应用专用下载目录中是否已有通过完整校验的目标 APK；有则直接进入安装器。
2. 否则保留同版本 `.part` 文件。发起下载时，若文件非空，使用 `Range: bytes=<length>-` 请求续传。
3. 服务器返回 `206` 时追加写入；服务器忽略 Range 返回 `200` 时清空临时文件后重新下载，避免重复字节。
4. 每次网络重试保留临时文件；只有大小、摘要、包名、版本或签名校验失败时删除临时文件。
5. 下载完成后先报告校验阶段，再执行现有完整校验；校验成功后保存为目标 APK 并启动系统安装器。

## 界面与进度

`UpdateProgress` 增加阶段字段：`CONNECTING`、`DOWNLOADING`、`VERIFYING`。连接建立前显示连接状态；收到响应后显示已下载字节和总大小；下载完成后显示文件校验状态。进度回调限制为约 100ms 一次，保留首个、阶段切换和完成事件，避免高频 UI 重组拖慢下载。

## 网络与安全

- 保留 HTTPS、GitHub Release 资产来源、大小校验、SHA-256、包名、版本号和签名校验。
- 使用 `Accept-Encoding: identity` 和较大的缓冲区，保证 Range 字节数与文件长度一致。
- 不使用第三方代理或未公开接口，不保存账号、证件和支付信息。
- 连接失败、服务器不支持续传、文件校验失败分别记录可读错误；不因优化而自动安装未经校验的文件。

## 测试和验收

- 保留现有版本比较测试，新增进度阶段和断点响应决策测试。
- 模拟首次下载、206 续传、200 重启、网络中断后重试、校验失败清理和已完成文件复用。
- 真机验收：正常下载显示连续进度；断网后恢复不会从 0 开始；校验失败不会安装；安装器仍能打开。

## 非目标

本次不改变购票自动化流程、官方 12306 交互、账号登录和支付行为。
