# 12306 冷启动首页导航设计

## 目标

任务只需在行程助手中保存日期、出发站、到达站、车次、席别、乘车人和开售时间。开售闹钟触发后，应用尝试唤起官方 12306，从首页进入车票查询，填写任务信息并通过官方页面完成一次订单提交。验证码、登录失效、身份核验、风控、候补协议和支付始终交给用户。

## 状态机

主流程为：

```text
SALE_T0 -> COLD_START -> OPENING_OFFICIAL_APP -> OPENING_HOME
-> FILLING_SEARCH_FORM -> WAITING_SEARCH_RESULT -> VALIDATING_SEARCH_RESULT
-> SELECTING_TRAIN_SEAT -> SELECTING_PASSENGER -> VALIDATING_ORDER
-> SUBMIT_ACTION_SENT -> WAITING_SERVER_RESULT -> PENDING_PAYMENT
```

每个状态都持久化到 `TaskStore`，并记录当前窗口包名、页面状态、动作结果、尝试次数和失败原因。状态只在页面证据满足唯一性和上下文约束时前进；空树、未知页面、非官方窗口、节点缺失或节点不唯一进入 `TAKEOVER`。

## 冷启动编排

开售阶段启动前台服务并记录 `SALE_T0`。服务检查无障碍服务和当前官方窗口：官方 App 不在前台时调用系统启动 Intent，记录 `OPENING_OFFICIAL_APP` 和启动尝试；随后等待包名为 `com.MobileTicket` 的窗口事件。窗口出现后，首页导航阶段只寻找唯一的车票/查询入口，不使用坐标或全页面第一个同名文本。官方 App 启动失败、超时或被后台启动限制阻止时保存可恢复失败状态并人工接管。

查询表单阶段分别填写出发站、到达站和日期，严格选择唯一且名称完全相等的候选项。点击查询后刷新页面树并等待结果加载，不以旁路 `queryG` 结果作为 UI 操作门控。结果页校验日期、路线和车次上下文，再在目标车次局部容器内选择席别和预订按钮。

## 提交和恢复

提交锁只在找到唯一可点击的“提交订单”控件后获取。点击返回 `false` 释放本次锁；返回 `true` 只表示动作已派发。提交后必须识别官方订单号以及日期、车次、席别、乘车人和金额证据，才进入 `PENDING_PAYMENT`。登录、验证码、风控、身份核验、官方页面改版和用户手动返回/切换 App 均停止自动点击并记录具体原因；恢复时不自动重复提交。

## 隐私、兼容性和验收

诊断只保存脱敏的阶段、状态码、窗口包名、字段类型和哈希，不保存账号、证件号、手机号、密码、订单号、金额或完整页面树。界面提示 Android 后台启动限制、厂商电池策略、无障碍权限和官方页面改版风险。单元测试覆盖状态转换、冷启动失败恢复、窗口切换、空树、节点唯一性和提交幂等；真机验收覆盖未启动/首页/其他页面、慢加载、手动返回、登录失效、验证页面和提交后官方订单核对。

## 事实边界

本功能只通过官方 12306 页面和无障碍服务操作，不调用未公开下单接口，不绕过任何官方验证，也不保证抢票成功或服务端在固定时间内生成订单。
