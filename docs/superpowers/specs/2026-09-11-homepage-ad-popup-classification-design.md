# 12306 首页广告与普通弹窗识别设计

日期：2026-09-11  
范围：`v0.3.3-auto-query` 后续修复

## 背景

诊断文件 `ticket-assistant-diagnostic-20260911-191436.json` 显示任务的开售判断正确，但官方页面被记录为 `POPUP`，随后进入人工接管。用户截图显示页面实际是 12306 首页：查询表单可见，顶部为活动广告横幅，底部为公告滚动条。当前分类器只根据整页文本判断，因同时出现“活动/公告”和“关闭”而误判。

## 目标

- 首页查询表单、导航、活动广告和公告栏存在时，仍识别为 `HOME_PAGE`，继续自动填写和查询。
- 只有真正阻塞页面的普通独立弹层，且弹层内存在唯一可点击关闭控件时，才自动关闭。
- 验证码、登录失效、身份核验、风控、候补协议和未知页面继续人工接管。
- 所有弹窗判定和关闭动作写入脱敏诊断，动作失败不得静默继续。

## 非目标

- 不点击或关闭首页广告横幅、公告滚动条、历史记录清除按钮或底部导航。
- 不使用坐标点击，不通过猜测关闭页面内容来绕过安全校验。
- 不处理验证码、滑块、实名核验、风控或支付。

## 方案

采用结构化弹窗匹配器，而不是在服务中按页面文字直接点击：

1. `PageStateClassifier` 调整判定优先级。具有首页导航或查询表单、且没有车次结果证据的页面优先判为 `HOME_PAGE`。仅有普通提示文字而没有首页证据时，文本分类仍可返回 `POPUP`，作为保守兜底。
2. 新增 `PopupMatcher`，遍历无障碍树寻找独立弹层容器。候选必须满足以下条件：容器具有对话框/弹出层语义（类名、资源 ID 或明确的弹层节点特征）；容器内包含普通公告、活动、优惠或温馨提示语义；容器内只有一个可见且可点击的关闭/知道了/暂不控件。首页横幅和公告条不满足独立弹层条件。
3. `TicketAccessibilityService` 先用 `PopupMatcher` 判断是否存在可安全关闭的弹层，再结合文本分类决定页面状态。匹配成功时只执行一次该候选的点击，记录 `POPUP_DISMISS_SENT` 及 `performAction` 结果，并等待下一次无障碍事件重新分类。匹配失败、候选不唯一或点击返回 `false` 时进入 `TAKEOVER`。

## 数据流与状态

```text
无障碍事件
  -> 读取页面树
  -> PopupMatcher 结构检查
       -> 唯一普通弹层关闭控件：点击并等待新事件
       -> 无匹配：PageStateClassifier
             -> HOME_PAGE：继续自动查询
             -> 其它 POPUP/UNKNOWN/敏感页面：人工接管
```

关闭动作成功只表示系统派发了点击，不表示弹层已消失。下一次事件仍需重新识别；如果弹层连续存在或页面无法分类，转人工接管并保留原因。

## 错误处理与安全边界

- 弹层候选必须唯一；不唯一不得选择“第一个”。
- 关闭按钮必须可见、可点击，并位于弹层容器内部或其可点击父节点内。
- 普通弹层关闭失败时停止自动动作，不重试坐标或其它同名控件。
- 弹层文字同时包含登录、验证码、身份核验、风控、滑块等敏感提示时，不自动关闭，立即人工接管。
- 诊断仅记录页面状态、候选数量、控件语义和动作结果，不记录账号、证件号、姓名或支付信息。

## 测试与验收

- 纯文本分类：截图同类首页内容（活动横幅、广告、公告、关闭/清除历史文案）必须为 `HOME_PAGE`；无首页证据的普通公告弹层仍为 `POPUP`。
- 弹窗匹配器：唯一关闭按钮可匹配；无弹层、首页公告条、多个关闭按钮、不可点击按钮和敏感弹窗均不可自动关闭。
- 服务行为：关闭动作返回成功后等待新事件；返回失败、树为空或候选不唯一时进入 `TAKEOVER` 并写入诊断。
- 回归：现有查询表单、车次选择、席别、乘车人、提交订单和待支付状态测试全部通过。
- 发布前运行单元测试、Lint 和 Release APK 构建；版本号递增并在正式 Release 中保留变更说明。
