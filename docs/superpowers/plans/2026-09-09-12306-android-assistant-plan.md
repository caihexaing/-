# 12306 Android 辅助 App 实现计划

## 阶段 1：工程骨架

- 创建原生 Kotlin Android 工程，`minSdk 26`，`targetSdk 36`，单 Activity + Jetpack Compose。
- 添加本地持久化、网络、通知和闹钟所需的最小依赖。
- 建立 `data`、`domain`、`ui`、`automation`、`notifications` 包边界。
- 验证无网络时仍可打开首页并显示权限状态。

## 阶段 2：真实车站与车次查询

- 实现官方车站资源下载与本地缓存，解析站名、电报码和城市字段。
- 实现查询会话初始化、动态读取查询端点和真实车次响应解析。
- 对网络失败、返回 HTML 错误页、字段缺失和日期超范围给出可恢复错误。
- 在列表中显示真实车次、发到时间、历时、席别/余票原始状态和起售时间；不以假数据兜底。

## 阶段 3：任务配置与本地存储

- 首页支持标准车站搜索、日期选择和查询。
- 车次详情页按“车次 → 席别 → 一名成人乘车人姓名 → 开售时间核对”的顺序配置。
- 使用 Android Keystore 保护乘车人姓名；其余任务存储在本地数据库或 DataStore。
- 订单预览必须勾选真实待支付订单授权，才允许启用唯一任务。

## 阶段 4：倒计时、通知和恢复

- 使用精确闹钟注册 `T-10 分钟`、`T-30 秒` 和 `T` 事件。
- 开售前通知、声音和震动可独立开关；任务状态变化持久化。
- 处理重启、时区变化、任务过期、停用和最长运行时长（默认 2 小时）。
- 增加“立即测试打开 12306”和运行环境诊断页。

## 阶段 5：官方 App 辅助状态机

- 检查官方 12306 包名与安装状态；通过显式 Intent 唤起。
- 声明并引导用户手动开启可选无障碍服务；服务仅匹配官方包名和本 App。
- 以可访问文本、控件标识和页面结构识别查询页、车次、席别、乘车人和订单核对页。
- 单次任务只允许一次提交；验证码、登录、身份核验、限流、页面变化或结果不明时进入接管状态。
- 成功进入待支付页后停止自动化并发出高优先级通知。

## 阶段 6：验证与交付

- 单元测试：站名解析、车次响应解析、任务快照字段核对、轮询退避和一次性提交锁。
- 真机测试：Android 16 安装、通知权限、精确闹钟、重启恢复、后台/可靠模式和官方 App 唤起。
- 真实联调前先完成“测试打开 12306”和页面识别诊断，再使用用户真实行程创建一次真实待支付订单。
- 输出 debug APK、源码、安装说明和已知限制；不上传账号、密码或个人证件信息。

## 当前环境限制

本机当前未发现 `java`、`gradle` 或 Android SDK 命令，因此在安装 Android 构建工具前无法本地编译 APK。源码可以先完成，构建验证需在装有 Android Studio/JDK 17/SDK 36 的环境执行。
