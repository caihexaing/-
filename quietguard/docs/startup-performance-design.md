# 0.4.4 启动兼容与扫描开销

用户实测0.4.3不再显示广告，但住理生活进入后黑屏几秒、恢复后还要等待才进入主页。没有设备日志，不能确定是广告SDK等待失败回调、原应用自身加载或无障碍开销造成。

可由代码确认：0.4.3每220ms轮询，而且任意窗口事件会取消轮询并立即在主线程遍历最多1200节点，事件频繁时扫描更密集。改为单一HandlerThread拥有全部扫描状态；事件合并，不突破每次扫描完成后500ms的间隔。先使用系统按文字查找跳过和广告标识；找不到必要证据时，最多每2500ms做一次有界广度遍历，每次在节点调用之间检查80ms预算。单次系统调用本身仍可能耗时，不能把预算当作硬性延迟保证。诊断增加最高单次读取耗时。两次点击尝试后的观察结束即停止扫描；过期窗口的同包事件不再唤起读取。

长按应用的防护方式增加“仅开屏跳过（启动兼容）”：主开关的选中列表仍控制无障碍，但该应用从VPN允许列表排除，使用原网络，不做广告域名阻断；开屏广告可能短暂出现，由已有按钮识别关闭。页面内其他广告不再使用域名过滤。默认保持旧的网络过滤+跳过，用户主动为住理生活选择，不暗改所有应用。纯跳过兼容独立保留。

全部选中应用都仅跳过时，不申请或启动VPN，关闭已有隧道但不关闭总防护和无障碍。混合模式只把需要网络过滤的应用传给VPN。更新恢复逻辑也以网络子集为准，不能因更新重新接管只跳过应用。切回网络过滤仍经过原VPN授权和更新暂停协调。

验证纯Java限频/事件风暴/路由集合/重试上限、已有核心检查、编译和Lint；发布0.4.4构建10，核对APK签名和更新源。无连接真机，不宣称黑屏已根治；需要用户在同一应用切换方式对比启动等待和实际跳过效果。
