# 0.4.2 直连更新下载设计

触发：用户在 iQOO 12、校园 Wi-Fi 下载时长期显示 0% 和系统排队。代码确认旧 UI 没有排队等待上限，无法仅据此判断设备端实际阻塞原因。

改用用户点击启动的 dataSync 前台服务，后台线程执行 HTTPS 传输到私有 files/update-downloads。Activity 只观察不可变状态，旋转和退出页面不取消传输。取消和超时关闭连接并中断线程，Activity/服务均有启动或任务等待上限。进程重启后已完成文件恢复校验，未完成任务明确提示重新下载。

主地址仍为指定仓库 Release；失败后使用同仓库 raw.githubusercontent.com/master/quietguard/download/QuietGuard-X.Y.Z.apk。发布工作流同时提交已校验签名的同一安装包与版本信息，保留版本化备用 URL。禁止第三方代理及关闭证书校验。初始地址绑定仓库和版本；跳转仅允许列出的 GitHub HTTPS 域名，最多五次跳转；连接和空闲读取各八秒，服务任务上限六十五秒。

主线路中断或文件损坏后，删除部分文件，从备用线路重新开始，不拼接不一致内容。字节进度来自实际读取；大小未知时显示已下载字节及不定进度。下载流 SHA-256 校验通过后保存完成状态；安装前再次核对 SHA-256、包名、版本和当前应用签名，并沿用只读 provider 与系统安装确认。

验证包含 HTTP 错误、连接/读取超时、DNS 失败、受信及不受信跳转、循环跳转、内容截断、大小未知、校园网登录页面、取消与备用文件覆盖。线上发布后运行同一 Java 下载类，验证真实主线路和强制主线路失败时的真实备用线路，核对已发布哈希；不将开发机测试称作 iQOO 校园网真机验证。
