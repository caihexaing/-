# 0.4.2 构建 8：基于 0.4.1 的 VPN 更新协调

用户已确认导致下载问题的是净屏自己的 VPN，要求从 0.4.1 重做 0.4.2：更新前关闭自己的 VPN，结束后恢复。保留系统 DownloadManager 和既有进度/校验流程，去掉前一构建的独立下载服务及备用文件发布。仅暂停网络隧道，不关闭全局防护选择或无障碍服务。

状态机保存临时暂停、恢复意图、检查 token、下载任务 id 和安装目标版本码。VPN 原本开启才记录恢复；原本关闭保持关闭。检查有独立 token 防止过期回调释放其他任务。先持久化状态，再关闭隧道，之后才发起网络请求或入下载队列。检查结束恢复；下载开始再暂停，终态、取消和失败均释放下载状态。连续 60 秒无进展时取消任务并释放，检查暂停最多 30 秒。

暂停期间保留已有 VPN 前台服务和状态通知，实际关闭 TUN 文件描述符；后台完成广播核对持久化任务 id，并查询系统下载服务真实终态，避免伪造广播提前恢复。恢复优先复用已有前台服务重建隧道；进程不存在时尝试启动，系统限制时保留恢复意图以供返回应用重试。授权失效时不弹后台授权、不抢占其他 VPN，显示恢复入口。所有 Android 状态迁移在主线程进行。

安装前再次暂停 VPN 并持久化原运行意图，MY_PACKAGE_REPLACED 接收器在新包替换后恢复；安装取消/返回应用也清理安装状态。手动暂停防护清除恢复意图，优先于更新流程。新修订版首次安装时，旧版没有这些代码与记录，不承诺首次旧版下载或安装就能执行自动化。

版本名保留 0.4.2，versionCode 8，高于旧构建 7。保留旧构建的归档标签，再将当前 0.4.2 发布标签与附件更新为修订版，更新文件严格递增版本码。0.4.1 可识别 0.4.2；旧构建 7 因自身同名版本比较限制需手动覆盖安装，修订版支持后续同名高版本码检测。检查更新使用唯一查询参数与禁缓存请求头，防止旧更新文件长期滞留。

验证：31 项状态机检查覆盖原开/关状态、取消/失败、过期 token、重复/非本任务完成、手动暂停、跨进程安装意图及权限失效；15 项版本检查覆盖同名修订。保留 91 项 DNS、56 项开屏、30 项完整性及 20,000 组随机报文检查。仍需真机覆盖开启 VPN、后台下载、取消、安装取消、替换安装、系统杀进程和权限撤销，不把 JVM 状态机验证称作 Android 实际恢复验证。
